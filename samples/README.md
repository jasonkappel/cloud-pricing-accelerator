# Sample fixtures (all synthetic)

Workbook fixtures are generated by `generate_fixtures.py`. Everything here is fictional test data with clean document properties
(no author, no sensitivity label, no tenant or site id, no file paths). Regenerate anytime with
`py generate_fixtures.py`.

## `synthetic_intake_completed.xlsx`

A completed, in-scope intake for the fictional app "StatementHub (synthetic)". Use it as the happy-path
ingestion fixture.

- In scope for v1: Windows + Linux IaaS VMs, managed PostgreSQL, attached block storage.
- Structure (the RC result to expect without re-discovering): three Excel tables (`T2Servers`, `T3Databases`,
  `T4Storage`) with real data rows, and two fixed-range sections (`1 App Basics`, `Platform + FinOps`) that
  need range parsing, not table reads.
- Two deliberate open Gaps so you can build the CompletenessGate DraftBenchmark path:
  - `compute-3.runtime` covers the `app-test` server Runtime of "Unknown" (an app-fact gap,
    material: no run-hours). Gap identity is bound to the normalized unit ID, not the editable name.
  - Platform/FinOps `P1` (approved regions) is left open (a pricing-policy gap, material: no region to price
    against).
- With both open, the expected state is DraftBenchmark (per-cloud provisional numbers, no summary headline,
  no export) until they are answered or defaulted by policy.

## `synthetic_intake_completed_expected.json`

The expected normalized facts and Gaps for the workbook above. Use it as the assertion target for the
ingestion/normalization Function.

## `reject_ole2_sample.bin`

A minimal file carrying the OLE2 compound-file signature (`D0 CF 11 E0 A1 B1 1A E1`). Use it to test the
magic-byte reject path: ingestion must reject it with "Legacy binary format detected. Open in Excel and Save
As .xlsx to continue" without parsing or converting.

## `skumap_seed_v1.json`

The seed SkuMap for the v1 families (Windows VM, Linux VM, attached block storage, PostgreSQL): the
multi-meter AWS-to-Azure mappings with MatchClass, capability evidence, candidate options, and quantity
formulas. It carries NO rates by design; rates live only in the dated PriceBook the harvester publishes.
The pricing engine loads component roles, MatchClass values, evidence, formulas, and identifiers from this
approved map and binds the canonical digest to every Comparison.

## `skumap_approval_v1.json`

A non-production approval record that binds the synthetic AWS-qualified reviewer, timestamp, and exact
SHA-256 content digest of `skumap_seed_v1.json`. Changing the SkuMap bytes invalidates pricing.

## `pricebook_seed_v1.json`

A dated, Published, non-production demo extract from authenticated snapshot `trust-20260922e`. It records
the extract digest separately from the parent snapshot identity and hash, and carries source SKU, meter,
and row identifiers for harvested rates. Azure RHEL software uplifts are isolated as visible demo
assumptions because they are outside the current Azure Retail Prices harvest scope. Compute commitment
candidates are pinned to three-year All Upfront terms: Savings Plan entries use their published effective
hourly rates, while AWS Standard RI and Azure Reservation term charges are normalized over 26,280 hours.
Storage and software rates remain undiscounted. It is not suitable for customer purchasing decisions.

## `pricebook_extract_approval_v1.json`

A separate POC approval record binding the exact canonical demo-extract digest to the authenticated source
snapshot ID and content hash. The pricing engine fails closed if the extract, its rate provenance, or its
source binding changes without an updated approval record.

## Validation is more than magic bytes

`PK` (`50 4B`) proves a ZIP, not a valid or safe workbook. Any zip, a renamed `.xlsm`, a malformed package,
or a zip bomb also starts with `PK`. The ingestion contract must: fast-reject OLE2 via its signature, then
validate the OpenXML package (require `[Content_Types].xml`, `xl/workbook.xml`, and valid relationships),
reject macros/external links/encryption, reject DTD/entity declarations, bound worksheet dimensions,
expanded size, and compression ratio, and malware-scan before parse. The API implements
the package controls and renamed-plain-zip test; the production Blob-trigger path must add the
malware-scanner gate before its deployment lock is removed.
